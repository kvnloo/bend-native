name: z0-stack
description: Use bundled downstream z0 observation, source-backed state, opportunities and the canonical local runtime.
---
Run `hermes z0 status` to inspect configuration and exact bundled source revisions.
Use `hermes z0 state /absolute/repo` for a State Packet and `hermes z0 opportunity /absolute/repo 'question'` for the existing deterministic action-space baseline. These commands read Git and repository documents. They do not read personal transcript stores or call models.

State evidence is not an authority grant. A legal transition is not an execution or verified outcome. Never treat Bend's emitted-book receipt as full task success.

Enable `plugins.entries.bend.settings.stack_mode: shadow` to collect metadata. Enable `stack_opportunities: true` separately to record bounded user requests and build background opportunities. Neither setting changes prompts, context engines, tool decisions, or provider routing.

Use `hermes z0 report` for API-attempt outcome joins. Use `hermes z0 score examples.jsonl --backend laya_421m --z0-root /repo --z0-home /state --python /venv/bin/python` to invoke an explicitly configured existing backend in its own environment. Use `hermes z0 evaluate scored.jsonl` on examples scored by an existing z0 DecisionBackend. API failure labels concern API attempts; observed tool behavior is not an optimal-action label. Evaluation never promotes a mechanism.

For configured model, worker, economics and authority services, use `hermes z0 runtime providers` to inspect the existing local z0 service. Submit the service's canonical JSON contract with `hermes z0 runtime route --request-file request.json` or `worker`. The service owns admission, explicit remote consent, route and execution receipts. Do not invent missing cost, success, or authority fields. Do not retry a worker dispatch automatically.
